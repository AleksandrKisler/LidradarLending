# LidRadar — лендинг (черновик)

Статический сайт без сборки: `index.html`, `assets/styles.css`, `assets/app.js`. Дизайн по Material Design 3 (тональная палитра от фирменного `#6c55ff`, Roboto Flex, Material Symbols, светлая и тёмная тема). Тексты взяты из `Lidradar/marketing/LANDING.md`, блок «Пилот» переписан под бесплатный бета-тест: закрытое боевое тестирование стартует 15 октября, публичный релиз 19 ноября.

## Хронология проекта

Блок сразу после первого экрана: горизонтальный таймлайн (`<ol id="tl">` в `index.html`, стили `.tl*` в `assets/styles.css`). Каждое событие — `<li class="tl__item">` с датой в `data-date` (ГГГГ-ММ-ДД) и номером позиции в `style="--c:N"` (от 1 до 10). Подписи чередуются сверху и снизу через классы `tl__item--top` и `tl__item--bottom`.

- Прошедшие события отмечаются галочкой, ближайшее подсвечивается, линия заполняется до сегодняшней даты. Это считает `assets/app.js` при загрузке страницы, ручных правок классов не нужно.
- Событие с атрибутом `data-pending` (сейчас 14 января 2027) показано пунктиром и в расчёт не входит. Когда оно подтвердится, уберите атрибут и класс `is-pending`, замените текст.
- Чтобы добавить событие, нужно увеличить число колонок сетки (`repeat(11, …)` в `.tl`, `88.888%` и `11.111%` в `.tl__axis`) и пересчитать `--c` у остальных. Для одного-двух событий проще заменить существующий текст.
- Событие от 30 сентября: в исходных данных стояло «31 сентября», такой даты нет. Если нужна другая дата, поправьте `data-date`, `datetime` и текст.

## Запуск

```bash
node server.mjs
```

Откройте http://localhost:5180. Нужен Node 20+, зависимостей нет. Сервер раздаёт сайт и принимает заявки с формы (раздел «Приём заявок»). `python3 -m http.server` годится только посмотреть вёрстку: приёма заявок на нём нет, форма покажет ошибку отправки. Шрифты и иконки подгружаются с Google Fonts, без интернета сработают запасные системные шрифты, а иконки пропадут.

Проверки (правила формы и сервер приёма): `node --test`.

## Приём заявок

Форма отправляет заявку на `/api/lead`. `server.mjs` проверяет поля теми же правилами, что и браузер (`assets/validate.js`), и дописывает одну строку JSON в файл **`leads.jsonl` рядом с `index.html`**. Файл создаётся при первой заявке с правами `600`, лежит в `.gitignore` и в репозиторий не попадает.

**Файл не отдаётся по адресу сайта.** Сервер отвечает 404 на всё, кроме `index.html`, `assets/` и `legal/`, поэтому `leads.jsonl`, `server.mjs`, `README.md` и `.git` снаружи недоступны. Это важно: в файле персональные данные. Если перед сервером стоит nginx или Caddy, проксируйте на `server.mjs` весь сайт (пример ниже), а не раздавайте каталог напрямую.

Строка заявки:

```json
{"date":"2026-10-17 14:34:14","receivedAt":"2026-10-17T11:34:14.904Z","id":"6c1f…","name":"Дмитрий Соколов","company":"Студия «Блик»","business":"Автосервис","contact":"@dmitry_s","locations":3,"source":"yandex / cpc","status":"Новая","consent":true,"consentDoc":"sha256:8fa85f82d4a3"}
```

`date` — московское время, `receivedAt` — UTC. `status`: «Новая» или «Повтор» (тот же контакт уже оставлял заявку). `source` — метки рекламы или сайт-источник, иначе «прямой заход». `consentDoc` — отпечаток текста `legal/consent.html`, который видел посетитель: по нему видно, на какую редакцию согласия он согласился (меняется при любой правке этой страницы). IP-адрес и User-Agent не сохраняются, в журнал сервера имя и контакт не попадают.

Читать на сервере:

```bash
tail -f leads.jsonl                       # новые заявки по мере поступления
wc -l leads.jsonl                         # сколько всего
jq -r '[.date,.name,.company,.business,.contact,(.locations//""),.source,.status]|@tsv' leads.jsonl   # таблицей
```

Файл можно править руками: сервер переживает пропавший перевод строки в конце и испорченные строки.

**Защита от мусора:** поле-ловушка для ботов, повторная отправка той же заявки не создаёт вторую строку, не больше 5 заявок с одного адреса и 30 со всего сайта за 10 минут, тело запроса до 8 КБ.

**Настройки** (переменные окружения): `PORT` (5180), `HOST` (127.0.0.1; `0.0.0.0` открывает порт наружу), `LEADS_FILE` (другой путь к файлу; внутри `assets/` и `legal/` нельзя), `TRUST_PROXY=1` (за nginx или Caddy: адрес посетителя для лимита берётся из `X-Forwarded-For`).

**Production (Docker).** В боевом стеке лендинг запускается контейнером `landing` рядом с приложением, за общим Caddy на своём домене (`lid-radar.online`). `Dockerfile` кладёт в образ только `server.mjs`, `index.html`, `assets/` и `legal/` (`.dockerignore` не пускает туда `leads.jsonl`, тесты и `.git`), заявки пишутся в том `/data/leads.jsonl`. Образ собирает `scripts/build-landing-image.sh` из репозитория бэкенда (`--landing-dir` с путём к этому каталогу): тег образа — первые 12 символов git sha этого репозитория, собирать можно только из закоммиченного дерева. Развёртывание, чтение заявок, копии и очистка по сроку — `Lidradar/docs/runbooks/vps-spaceweb-deployment.md`. Примеры ниже (systemd, nginx) нужны, если запускать без Docker.

Пример для systemd (`/etc/systemd/system/lidradar-landing.service`):

```ini
[Unit]
Description=LidRadar landing
After=network.target

[Service]
WorkingDirectory=/srv/lidradar-landing
ExecStart=/usr/bin/node server.mjs
Environment=PORT=5180 HOST=127.0.0.1 TRUST_PROXY=1
User=lidradar
Restart=on-failure
NoNewPrivileges=true

[Install]
WantedBy=multi-user.target
```

Пример для nginx (весь сайт идёт через `server.mjs`):

```nginx
location / {
    proxy_pass http://127.0.0.1:5180;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    client_max_body_size 16k;
}
```

**Что нужно делать с файлом, раз он ваш:**

- Хранить не дольше 12 месяцев (так обещает политика сайта). Оставить свежие: `jq -c 'select(.receivedAt > "2026-01-01")' leads.jsonl > leads.new && mv leads.new leads.jsonl` (подставьте дату на год назад, сделайте копию перед правкой, на время замены лучше остановить сервер).
- Отзыв согласия: удалить строки человека в течение 30 дней, например `jq -c 'select(.contact != "@name")' leads.jsonl > leads.new && mv leads.new leads.jsonl`.
- Резервные копии файла содержат персональные данные: хранить на территории РФ и под тот же срок.
- Журналы веб-сервера (nginx, journald) хранить не дольше 30 дней, как сказано в политике сайта.
- Сервер должен находиться в РФ (часть 5 статьи 18 152-ФЗ), провайдера записать в `docs/legal/requisites.json` репозитория backend.

## Снимки интерфейса

Пять изображений в `assets/img/` (WebP, 2× плотность) показывают настоящий клиент LidRadar, а не макеты:

| Файл | Где на странице | Что на снимке |
|---|---|---|
| `ui-onboarding.webp` | «Четыре шага» | Шаг 4 мастера: Telegram Business подключён, все шаги «готово» |
| `ui-radar.webp` | Radar | Сводка (2 риска, 47 000 ₽ под риском, 147 000 ₽ возвращено) и критичный сигнал |
| `ui-risk-card.webp` | Карточка сигнала | Почему это риск, статус и «Взять в работу», переписка, оценка сигнала |

- Экраны сняты с работающего клиента на демонстрационных данных, поэтому под каждым стоит подпись «Демонстрационные данные». Набор цифр тот же, что в тексте блока «Деньги»: 24 → 18 → 11, 147 000 ₽ за 7 дней.
- Размеры заданы атрибутами `width` и `height`, картинки грузятся лениво (`loading="lazy"`), рамка и тень описаны классом `.shot` в `assets/styles.css`.
- Как переснять экраны после изменений интерфейса: `Lidradar/marketing/capture/README.md`.
- Пример сигнала в блоке Radar (`.risk-card`) повторяет верхнюю карточку на снимке: «Критично», Дмитрий Соколов, 31 000 ₽. Если меняете данные на снимке, поправьте и его.

## Что нужно доделать

1. **Форма бета-теста: развернуть приём.** Заявки принимает `server.mjs` и пишет в `leads.jsonl` (раздел «Приём заявок»). Остаётся запустить его на сервере в РФ и заменить заглушку `[КОНТАКТ]` в сообщении об ошибке формы. Старый скрипт Google Apps Script из репозитория убран, но опубликованное веб-приложение по адресу `/exec` из истории git продолжает принимать заявки: отзовите публикацию в Apps Script («Управление развёртываниями»), а уже накопленные в Google Таблице заявки перенесите в файл и удалите в Google.
2. **Снимки интерфейса** уже вставлены (см. раздел ниже). Остаётся заменить демонстрационные экраны на скриншоты работающего клиента с реальными данными, когда они появятся, и убрать подпись «Демонстрационные данные».
3. **Поля `[В СКОБКАХ]`** подсвечены жёлтым: контакт в сообщении об ошибке формы, e-mail, Telegram и реквизиты самозанятого в футере. Значения те же, что в `docs/legal/requisites.json` репозитория backend.
4. **Дата релиза** задана в `assets/app.js` (`RELEASE`) и в `index.html` (`<time datetime="2026-10-15">`). Обратный отсчёт считается по дате посетителя.
5. Мета-теги для соцсетей: `og:url` и `canonical` указывают на https://lid-radar.online/. Добавьте `og:image`, когда будет картинка.

## Юридические страницы

Пользовательское соглашение, политика конфиденциальности и согласие на обработку данных лежат в `legal/` (`terms.html`, `privacy.html`, `consent.html`, `index.html`). Это **сгенерированные файлы**: руками их не правят. Источник — Markdown в `docs/legal/landing/` репозитория backend (`Lidradar`) и реквизиты в `docs/legal/requisites.json`. Пересборка из каталога backend:

```bash
node scripts/build-legal.mjs --app <каталог веб-клиента> --landing <каталог этого лендинга>
```

Ссылки на них стоят у чекбокса согласия в форме и в футере. Подробности, список действий перед публикацией и правила изменения: `docs/legal/README.md` в репозитории backend.

**Перед публикацией сайта в России нужно привести в соответствие с документами одно место, иначе политика на сайте будет неверной:**

- Шрифты и иконки грузятся с Google Fonts (`index.html`, строки с `fonts.googleapis.com`). Браузер посетителя при этом передаёт его IP-адрес Google. Файлы шрифтов нужно положить в `assets/fonts/` и подключить через `@font-face`.

Приём заявок политике уже соответствует: файл на вашем сервере в РФ, сторонние сервисы не участвуют (раздел «Приём заявок»).
